# The Geometry example

The situation, in five steps:

1. your application has an internal Ada API — one package,
   `Geometry`, in `src/`;
2. you want HAC scripts embedded in your application to call it;
3. one `hac-bindgen generate` command writes the binding glue;
4. the generated files land in `generated_src/`, `src/` untouched;
5. a script calling `HAC_Geometry.Distance` runs in the embedded VM
   and prints the distance.

The Ada glue shown in this page is **actually generated by the
current version of hac-bindgen** (`make build` puts the tool in
`bin/`), and **verified by the three bbt scenarios** at the bottom:
every `make doc` from the repository root re-runs the whole chain —
generation, dry-run check, build, and the script execution whose
output must contain `distance = 5.0`.

Prerequisites: `make build` (hac-bindgen) and `make backend` (the
Libadalang analysis backend in `tools/libadalang_backend/bin/`).

## 1. The API you already have

`src/geometry.ads` is an ordinary package specification — no pragma,
no convention, nothing written for hac-bindgen's sake:

```ada
package Geometry is

   type Point is record
      X, Y : Integer;
   end record;

   procedure Translate (P : in out Point; Dx, Dy : in Integer);

   function Distance (A, B : Point) return Long_Float;

   function Midpoint (A, B : Point) return Point;

end Geometry;
```

The body (`src/geometry.adb`) is your own code, as always.

## 2. The command

```sh
hac-bindgen generate src/geometry.ads \
   --output-dir generated_src --hac-package HAC_Geometry
```

`--hac-package` renames the script-facing package: the scripts
`with` `HAC_Geometry`, while the native build still compiles the real
`Geometry` — two worlds, two unit names, no clash with GNAT.
`check` runs the same analysis first and writes nothing: it reports
**2 operations bound, 1 not bound (see warnings)** — `Midpoint`
returns a record, and HAC function results are atomic types only
([HACB0005]): warned out, never silently dropped.

## 3. The generated files

`generate` writes to `generated_src/`; `src/` stays untouched:

| Generated file | Side | Role |
|---|---|---|
| `generated_src/hac_geometry.ads` | script | the package the script `with`es: the mirrored `Point`, the imported declarations that reach your native code |
| `generated_src/hac_geometry.adb` | script | the function wrappers calling the imported callbacks |
| `generated_src/geometry_native.ads/.adb` | native | one callback per bound operation, and `Register_All`, to call from your embedding main |

## 4. The embedding application

`demo_main.adb` is your application: it registers the generated
binding once, then hands the HAC VM the script passed as argument:

```ada
Geometry_Native.Register_All (BD);
BD.Build_Main_from_File (Script);
HAC_Sys.PCode.Interpreter.Interpret_on_Current_IO (BD, 0, Script, Post_Mortem);
```

## 5. A script that works — the distance is 5

The script (`demo.hac`) is plain HAC-side Ada:

```hac
with HAT;
with HAC_Geometry;

procedure Demo is
   use HAT;
   A, B : HAC_Geometry.Point;
   D    : Real;
begin
   A.X := 0;  A.Y := 0;
   B.X := 3;  B.Y := 4;
   D := HAC_Geometry.Distance (A, B);
   Put ("distance = ");
   Put (D, 1, 1, 0);
   New_Line;
end Demo;
```

HAC resolves the units a script `with`es by file name, relative to
the current directory — so run from the generated side:

```sh
alr exec -- gprbuild -P demo.gpr     #  or: make doc
cd generated_src && ../demo_main ../demo.hac
```

Output, executable proof that the native call crossed the boundary:

```text
distance = 5.0
```

Everything the runs leave behind — build objects, the binary, the
bbt dumps, and the generated binding itself — is removed with
`make clean` from `docs/examples`; the next `make build` or
`make doc` rebuilds it all.

## Scenario: generate the binding

- Given the directory `generated_src`
- Given the environment variable `HAC_BINDGEN_BACKEND` is `../../tools/libadalang_backend/bin/hac_bindgen_backend`
- When I successfully run `../../bin/hac-bindgen generate src/geometry.ads --output-dir generated_src --hac-package HAC_Geometry`
- Then the exit code is `0`
- And there is a `generated_src/hac_geometry.ads` file
- And there is a `generated_src/geometry_native.adb` file

## Scenario: check reports the classification without writing

- Given the environment variable `HAC_BINDGEN_BACKEND` is `../../tools/libadalang_backend/bin/hac_bindgen_backend`
- When I successfully run `../../bin/hac-bindgen check src/geometry.ads`
- Then the exit code is `0`
- And the output contains `Geometry: 2 operations bound, 1 not bound (see warnings)`
- And the output contains `warning HACB0005: function Midpoint is not bound`

## Scenario: the demo runs, and the distance is 5

- When I successfully run `alr exec -- gprbuild -q -P demo.gpr`
- Then the exit code is `0`
- When I successfully run shell `cd generated_src && ../demo_main ../demo.hac`
- Then the exit code is `0`
- And the output contains `distance = 5.0`
